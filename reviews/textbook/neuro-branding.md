# NEURO branding and responsive layout

Reference: the latest user-supplied transparent NEURO Mindsets wordmark and monochrome neural-network example were inspected. The RGBA logo is copied unchanged to `public/neuro-mindsets.png`. Its lettering bounds are x=261–1802, y=224–483; the SVG display window includes both wordmark lines. Next Image handles delivery. Dark-mode grayscale inversion preserves the source alpha, without opaque backing or backdrop blending. All visible wordmark instances share this component.

Login omits the course header and keeps a dedicated Display control. A new, static SVG network uses fine lines and nodes with 4–12% opacity depending on theme and viewport, a quiet centre, no colour gradients, no animation, and no pointer or accessibility interference. Existing phone/tablet stacking remains. Apple system typography is the default for UI and reading, with portable system fallbacks and no font downloads. Previously saved learner font preferences remain valid; the four reading choices and font-size range stay available.

The site uses restrained white/graphite surfaces and blue accents, a branded two-profile login, actual chapter navigation and progress, and actual learning objectives. The reference mockup’s fictitious course structure and progress are not imported. Course content, video identity/placement/review data, assessment data, backend authentication, and save APIs are unchanged. Existing display preferences and reading-mode behavior remain, including the four fonts and 16–28 px size range.

Responsive contracts: 1440+ px three columns; 1024–1439 px two columns; under 1024 px chapter toggle plus stacked progress/goals and reader; under 768 px stacked login and header navigation row; under 540 px compact wordmark/account controls and vertical previous/next links. Phone/tablet chapter navigation closes on chapter changes. Goal completion is not inferred from a chapter check.

Verification: production build/type/lint checks, all existing tests plus login access and font preference checks, static chapter/video markup checks, and live route/logo checks. Browser visual and interaction QA remains unavailable in this managed environment (no control-browser skill); viewport styles and contracts are implemented, but actual device screenshots/playback/touch behavior were not verified. The existing online-storage provisioning limitation is unaffected.

Mobile navigation revision: below 1024 px, the header is a single sticky row with navigation and Display buttons. A native `<dialog>` provides a left drawer, focus containment, Escape and backdrop dismissal, focus restoration, background scroll locking, safe-area padding, independent list scrolling, and a fixed profile footer. Chapters show the active lesson and each profile's completion checks. The inline mobile chapter sidebar and large pre-reader overview are replaced by the drawer; desktop layouts are retained. Display controls use unique IDs when mounted in both desktop and drawer contexts. Text weight 300/400/500/600/700 is validated, persisted, and restored before paint, with 400 for legacy settings. Headings/emphasis keep their existing hierarchy. Browser/device visual and gesture verification remains unavailable in this environment; production build, automated preference regression checks, and deployed HTML/asset checks are used.
